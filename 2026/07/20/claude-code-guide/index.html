Claude Code 完全使用指南

Claude Code常用终端命令

1.有关MCP的

利用 Project Scope，你可以实现”不同项目加载不同 MCP”，完美解决我们之前讨论的”MCP 装太多吃 Token”的问题！–scope选项默认是local，不是user

2.常用快捷指令

常见的MCP服务

1.chrome-devtools-mcp

Chrome DevTools MCP 是一个让 Claude 能够直接操作和控制你的 Chrome 浏览器的强大工具。

在https://github.com/ChromeDevTools/chrome-devtools-mcp有很多配置方式

命令：claude mcp add chrome-devtools --scope user npx chrome-devtools-mcp@latest

–scope user：意思是把该mcp服务作用与用户级别，也就是全局作用域中，配置在用户目录中的.claude/settings.json文件中，不管在任何目录中启动claude，都会加载这些MCP

2.Neon

Neon 是无服务器版 PostgreSQL 云数据库，完全兼容原生 Postgres，存算分离架构，自带免费套餐，还提供 MCP 远程接口对接 Claude 等 AI 工具。

核心作用：一是做业务数据库，存放网站、小程序、AI 应用结构化数据，支持向量存储做 RAG 知识库；二是通过 MCP 服务让 Claude 直接用自然语言建库、写 SQL、改表、管理数据库分支。

使用：

先注册 Neon 账号，终端执行claude mcp add --transport http neon https://mcp.neon.tech/mcp绑定远程 MCP 服务，重启 Claude 完成 OAuth 授权；之后直接对话让 AI 创建库、执行查询、做数据迁移；日常开发也能拿连接字符串在代码里直连数据库

3.12306铁路

claude mcp add 12306 --scope user -- npx -y 12306-mcp

Skills

1.什么是skills

skills是轻量化、可复用的标准化任务指令包，核心载体是SKILL.md文件，顶部 YAML 元数据定义技能名称、用途，正文是标准化流程、提示词、检查清单、操作模板，配套支持脚本、示例文件。MCP给ClaudeCode提供外部操作能力，而Skills则是叫ClaudeCode怎么正确规范的使用这些能力、按规范完成任务。

2.核心作用

把重复操作固化成规范步骤（代码审查、单元测试、接口文档生成、数据库 SQL 规范、项目部署流程），避免每次聊天重复粘贴大量提示词。

自动触发/手动触发：

  • 自动触发：AI读懂你的需求，匹配技能描述后自动加载执行
  • 手动触发：输入/技能名强制启动，例如/code-review启动完整代码质检流程

按需加载，节省上下文 Token

  • 未用到时只加载几十 Token 的简介，只有触发后才完整读取全部指令，不会长期占用窗口容量。

约束 AI 行为、统一输出规范

  • 限定输出格式、校验规则、安全边界，比如强制代码审查必须检查 SQL 注入、内存泄漏、注释完整性。

3.解决核心痛点

重复粘贴长提示词：不用每次对话复制全套规范，一次编写永久复用；

AI 输出不稳定：统一流程模板，每次执行标准完全一致；

上下文窗口浪费：长规则不会常驻会话，仅使用时加载；

团队规范难以落地：项目内放入 skills，所有人使用同一套开发 / 审查标准；

工具调用混乱：搭配 MCP 使用时，Skills 规定调用时机、参数格式，避免 AI 乱调用外部服务。

4.使用

就拿 frontend-design 来说，这是 Anthropic 官方推出的明星 skill，目前装机量已经超过 27 万次。它的核心作用，是把 Claude 生成前端代码时的那种「一眼 AI 味」给治好，让你拿到的页面更像真人设计师做出来的。

效果：

skills存储的位置：也分为全局skill和项目级skill

5.安装context7

Context7：给 Claude/Cursor 这类 AI 提供实时最新框架文档的工具（比如查 React、Vue、LangChain 最新官方文档，不会用过时知识库）

6.两种skill格式区分

官方推荐使用文件夹的形式存储，然后里面的md文档一定要大写，使用SKILL.md作为入口

① 独立 .md 文件（如 find-skills.md）

  • 判定标准：直接放在 skills/ 下、后缀 .md
  • 识别逻辑：单个文件就是单个独立 Skill，文件内写完整技能定义、触发逻辑、工具描述
  • 加载方式：启动时直接读取该 md 全文，注册为一条技能

② 文件夹形式（如 context7-mcp/）

  • 判定标准：skills/ 下存在文件夹，且文件夹内包含 SKILL.md
  • 识别逻辑：整文件夹视作一个完整 Skill 包，SKILL.md 是入口配置，文件夹里还能放配套脚本、说明、规则
  • 你的 context7-mcp 就是 MCP 配套技能，靠这个文件夹里的 SKILL.md 告诉 Claude：存在一个 MCP 服务可以调用

二、Claude 怎么区分「普通 Skill」和「MCP 服务」

  1. MCP 服务本身不在 skills 文件夹里

连接配置

  • .claude.json = MCP 服务注册表（AI 能调用哪些外部工具服务）
  • skills/ = 行为引导规则（AI 什么时候、怎么主动调用这些 MCP 工具）

2.skills 里的 context7-mcp 文件夹只是 “引导技能”

context7-mcp/SKILL.md 作用：

  1. 告诉 Claude：你拥有一个名叫 Context7 的 MCP 工具
  2. 设定触发逻辑：用户问框架 / 库代码时，自动调用 MCP 服务查最新文档
  3. 定义调用参数、返回结果怎么整理给用户

简单分层：

  1. .claude.json → 建立通信通道（连上 Context7 MCP 服务）
  2. skills/context7-mcp/ → 给 AI 下达使用指令（什么时候用这个通道）
  3. 普通 md 技能（find-skills.md）→ 纯本地逻辑，不依赖任何 MCP 服务

三、Claude 加载顺序 & 识别逻辑

  • 启动 Claude Code
  • 先读取 .claude.json，加载全部 MCP 服务（包括 Context7），缓存所有可用工具名称
  • 扫描 skills目录
    • 凡是 .md 文件 → 加载为单文件 Skill
    • 凡是内含 SKILL.md 的文件夹 → 加载为文件夹型 Skill
  • 所有 Skill 会同步读取，其中 context7-mcp 这个 Skill 会关联前面加载好的 Context7 MCP 工具，实现自动调用

Skills、MCP、Plugin区别

维度 Skills MCP Plugin（插件）
底层本质 Markdown 指令文档、标准化流程约束 通信协议，连接外部独立程序 / 服务 完整功能分发包，整合三者
核心能力 教会 AI「怎么做事」，规范流程、提示词 赋予 AI「新工具」，访问外部数据 / 程序 批量打包全套扩展 + 自动化钩子
是否新增外部能力 ❌ 不新增工具，只约束 AI 行为 ✅ 新增第三方操作能力 ✅ 可内置 Skills+MCP + 钩子
实现成本 极低，仅写 MD 文件 中高，需要编写服务端程序 中等，打包配置文件
生效范围 全局 / 项目两层目录隔离 用户全局 / 项目本地配置 全局安装，全项目生效
调用逻辑 AI 自动识别 / 手动 /技能名 AI 根据需求自动调用服务工具 安装后自动加载内部所有资源
典型例子 代码审查规范、SQL 编写模板、部署流程 Neon 数据库、12306 车票查询 MCP 官方 LSP 代码提示插件、Git 工作流插件

MCP 提供工具：比如 Neon 数据库 MCP，让 AI 能执行 SQL；

Skills 规范调用逻辑：写一个 sql-standard 技能，规定 AI 怎么写 SQL、何时调用 Neon MCP、输出什么格式；

Plugin 打包分发：把上面的 MCP 配置 + SQL Skills + 自动校验钩子打包成插件，一键分享给别人使用。

MCP = 工具入口：让 AI 能摸到外部软件 / 数据库；

Skills = 使用说明书：告诉 AI 正确、规范地使用这些工具；

Plugin = 工具 + 说明书 + 自动化脚本的完整安装包，一键部署整套扩展。
